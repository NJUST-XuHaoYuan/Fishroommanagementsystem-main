# AGENTS.md

## Project context

This project was primarily generated by AI. Treat the codebase as untrusted until verified.

## Shared integration baseline

- Work only in the checkout assigned to the task. Start by checking its branch and working tree.
- Before development or release, fetch `origin` and merge `origin/codex/current-base` into the task branch. Preserve existing uncommitted work before merging.
- `codex/current-base` is the shared integration baseline for the management system, public API, and WeChat Mini Program. After validating an integration, advance it with a normal fast-forward push; never force-push it.
- Before building a release or uploading a Mini Program package, verify `git merge-base --is-ancestor origin/codex/current-base HEAD`. If it fails, integrate the missing baseline first. Also verify the latest production or submitted-package commit is included; a stale baseline alone is not sufficient.
- Do not copy whole directories from another task over local changes. Merge commits and inspect overlapping files, including `wechat-miniprogram/app.wxss` and `wechat-miniprogram/pages/products/index.wxml`.
- Git integration, server deployment, Mini Program upload, review submission, and formal publication are separate states. Report only the state actually verified.
- See `wechat-miniprogram/README.md` for the cross-task Mini Program integration record.

## Review guidelines

Focus on serious issues, especially:

- Authentication and authorization gaps
- Business logic bypasses
- Backend trusting client-provided userId, role, price, status, permissions, or ownership fields
- Missing server-side validation
- Data consistency, transactions, idempotency, and duplicate submission risks
- Payment, order, subscription, billing, quota, or permission state bugs
- PII leakage in logs, errors, analytics, or client responses
- Secrets committed to code
- Unsafe file upload, SSRF, XSS, SQL/NoSQL injection, command injection
- Missing tests for critical business flows
- Mock, placeholder, TODO, fake implementation, or hardcoded demo logic
- Code paths that look complete but are not wired to real services
- Deployment config that works locally but fails in production

When reviewing, provide:
- Severity: P0/P1/P2/P3
- File path and line reference
- Why it matters
- Reproduction or verification steps
- Suggested fix
- Test that should be added

Do not spend review comments on minor style issues unless they hide a real defect.
